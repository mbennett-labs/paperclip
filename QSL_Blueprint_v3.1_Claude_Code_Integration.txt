PART 4.8: CLAUDE CODE  --  THE EXECUTION ENGINE
4.8.1 The Problem Claude Code Solves
Paperclip agents run as Claude sessions. By default, Claude sessions in Paperclip ask for permission before every shell command, file write, SSH connection, and API call. This makes autonomous operation impossible. Every heartbeat stalls waiting for a human to click Allow.

Claude Code with --dangerously-skip-permissions removes that wall. The agent runs every command autonomously, without popups, without approval gates, without stopping. This is the only way the swarm operates at the speed it needs to.

THE RULE
Every Paperclip agent MUST have --dangerously-skip-permissions in Extra Args.
Any agent without it is not a functional agent. It is a planning tool wearing an agent mask.
This is not a security shortcut  --  it is the intended production configuration for autonomous agents
operating on infrastructure you own and control.

4.8.4 The PowerShell Direct Execution Pattern
For complex multi-step tasks, or when Paperclip heartbeat context is too limited, use the PowerShell Direct pattern. This is Claude Code running outside Paperclip, used for one-shot complex operations:

EC2: ubuntu@3.20.79.143
Paperclip API: http://127.0.0.1:3100
When done, post results to Paperclip issue [ISSUE-ID].
Create a report at C:\Users\mikeb\paperclip\[REPORT].md

WHEN TO USE POWERSHELL DIRECT vs PAPERCLIP HEARTBEAT
Use Paperclip Heartbeat for: routine monitoring, regular status checks, scheduled content posts,
  simple single-step tasks that complete in one SSH command.

Use PowerShell Direct for: complex multi-step deployments, debugging sessions, initial setup tasks,
  anything requiring more than 5 sequential commands, blueprint updates, org rebuilds.

Rule of thumb: If you would back-and-forth in PowerShell more than 3 times, write one complete
  prompt and let Claude Code run it straight through.
