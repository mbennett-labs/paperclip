# Agent Commerce Company Blueprint

## Mission

Operate a dedicated Paperclip company for agent-native commerce research, product creation, launch experiments, and governed execution. The company exists to turn Board direction into small, testable, commercially relevant agentic-market missions while preserving human control, evidence, and clear authority boundaries.

## Operating Principle

Permanent executive core, temporary mission cells.

The CEO Mission Cell is durable. Most subordinate cells are created for a mission and retired when that mission reaches a terminal state. Institutional evidence remains after the cell disappears.

## Initial Organization

### CEO Mission Cell

Role: permanent company orchestrator.

Responsibilities:
- Receive Board directives.
- Convert directives into projects/issues/subissues.
- Create and supervise subordinate mission cells.
- Maintain the human-readable operating picture.
- Escalate decisions and questions.
- Enforce scope, permissions, budgets, and terminal conditions.

### Market Intelligence Cell

Role: opportunity discovery and verification.

Initial coverage:
- x402 and machine payments.
- MCP commerce/discovery.
- AWS AgentCore / AI agent distribution.
- Apify creator and agent-payment channels.
- Other relevant agent-native payment/distribution rails.

Outputs:
- Verified market facts.
- Ranked opportunities.
- Buyer/seller/volume/fee evidence when available.
- Product-shape observations.
- Explicit unknowns.

### Product Foundry Cell

Role: convert approved opportunities into bounded products.

Outputs:
- Product hypothesis.
- Input/output contract.
- Governance requirements.
- Implementation plan.
- Evaluation plan.
- Launch gate evidence.

### Commerce Cell

Role: packaging, pricing, distribution, and transaction integration.

Outputs:
- Pricing proposal.
- x402/MCP/API packaging.
- Marketplace/distribution configuration.
- Cost and fee model.
- Transaction and launch evidence.

### Governance & Evidence Cell

Role: independent verification of scope, permissions, provenance, and release readiness.

Outputs:
- Permission review.
- Evidence sufficiency review.
- Governance checkpoint recommendation.
- Launch blockers.
- Post-experiment evidence packet.

## Initial Project

Name: Agent Commerce Pilot 001

Objective: build and validate one narrow, machine-payable governed-intelligence service through an x402-compatible MCP/API surface, with a secondary distribution path where useful.

The project must begin with market evidence and a product hypothesis, not with autonomous implementation.

## Human Interaction Routing

### Inbox

Inbox is the urgency surface. It should contain only items that need human awareness or action soon:

- Decision Required.
- Question.
- Exception.
- Review Ready.
- Material Information.

Inbox should not become the canonical record. Each inbox item links to its canonical issue or approval record.

### Issues

Issues are the canonical units of work, state, discussion, evidence, and decision history.

Every material mission must have an issue. Every approval request must point back to the issue whose execution depends on it.

### Subissues

Subissues are decomposition and execution detail. Humans should not have to read all subissues to understand company state; the CEO must roll material state upward to the parent issue and Main UI.

### Comments

Comments provide contextual direction, questions, evidence review, and amendments. A comment does not grant new authority unless explicitly recorded as an approval/amendment decision.

## Standard Mission States

Proposed → Active → Waiting on Human → Blocked → Review Ready → Approved for Next Stage → Completed / Retired

Additional terminal state: Rejected.

## Mission Cell Promotion

Default: retire after mission completion.

Promotion to a durable capability requires evidence of repeated value and explicit Board approval. Promotion should define continuing mission, budget, authority, review cadence, and shutdown conditions.

## Company Bootstrap Sequence

1. Create dedicated Agent Commerce company.
2. Install Board → CEO contract as governing policy.
3. Create CEO Mission Cell only.
4. Create the Main UI / Board Desk surface.
5. Create AC-001 from the first Board directive.
6. CEO decomposes AC-001 and proposes required mission cells.
7. Board reviews only exceptional permissions/budgets; ordinary bounded decomposition proceeds under the contract.
8. Start Pilot 001.

## Non-Goals

- Migrating old email-company business state into this company.
- Making inbox, chat, or off-system conversation the authoritative operational record.
- Creating a large permanent agent hierarchy before missions require it.
- Allowing mission cells to recursively expand authority.
- Treating autonomous activity volume as success.

Success is commercially useful evidence produced under visible human control.
